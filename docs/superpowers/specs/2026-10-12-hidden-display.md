# 同一 Android 模拟器中的隐藏执行屏

用户已确认：主屏继续使用 YouTube 等 App，Agent 在默认不展示的副屏操作真实 App；需要时才查看执行画面。保持原有高风险操作限制。

## 验收条件

1. 一个 Android 实例内创建独立虚拟显示屏，不打开 Mac 镜像窗口。
2. App 启动、截图、控件树、触摸和按键必须绑定同一副屏；不读取主屏私人内容供模型决策。
3. 副屏不存在、身份改变、截图失败或控件来源不明时停止，不回退主屏。
4. 主屏保持原 App；验证副屏操作期间主屏视频及交互不被打断。未验证的音频/第三方 App 兼容性明确披露。
5. 保留任务暂停、取消、查询及独立结果验证。购物付款/下单不属于本轮验收范围。

## 实施顺序

- 先用 scrcpy 的虚拟显示机制做可丢弃探针，确认无窗口创建和定向输入/采集能力。
- 探针通过后，加入显示屏身份与生命周期配置，并以失败用例驱动设备隔离实现。
- 接入已有 worker 和鉴权截图预览；默认不展示执行画面。
- 完成自动化回归与真实模拟器验证，再切换运行服务。若底层能力不满足条件，保留已有执行方式，不宣称后台隔离已完成。

## 限制

虚拟屏仍与主屏共享 Android 用户、账号、音频及部分系统窗口。系统支持多显示屏不代表任意 App 都可隔离运行。先验收时钟，其他 App 逐项测试。

## 本机实施与验证记录

- Android 15（API 35）、scrcpy 5.0.1；以无窗口、无音频采集、无控制客户端创建副屏，屏幕退出时销毁内容，不将任务移到主屏。
- `serve --hidden-display` 管理副屏生命周期。配置保存逻辑显示编号、uniqueId 和 boot ID；每次采集和动作核对绑定，队列任务的设备身份也包含绑定摘要。
- 控件树按 `display-id` 过滤，缺失归属的节点丢弃。截图使用独立有时限的副屏采集进程，临时视频提取 PNG 后立即清理。触摸、滑动和返回均带显示编号；后续接入显式控件的副屏文字输入，见下述验证记录。
- 已实测副屏截图和标签点击，主屏 YouTube 播放进度从 0:45 前进至 1:17。真实模型任务 `7f1d3a2498ed4182b17c51631efd56a5` 在隐藏副屏进入闹钟页并核对 21:00 开关已启用，完成后仍保持主屏 YouTube。该任务仅核对已有闹钟，没有再次创建。
- 回归覆盖：禁止绑定主屏；副屏丢失、替换、设备重启时拒绝输入；控件树不暴露主屏；按键/触摸定向；不搬走用户主屏目标 App；创建失败/退出时清理副屏；服务离线后取消遗留任务。
- 控制台默认不请求截图，手动展开后才获取鉴权预览。预览不是交互式接管窗口；系统弹窗、音频焦点及第三方 App 尚需继续按场景验收。

## 定向文字输入

用户批准接入“副屏定位 → 指定控件写入 → 读取核验”。Android 桥接按显示编号枚举交互窗口，匹配包名、resource ID、类名、边界、原文字及描述，要求唯一、可编辑、可见、启用、非密码且支持 ACTION_SET_TEXT。动作前再次检查显示身份、启动标识、节点及其窗口归属；动作后读取原节点验证文字。不会点击、改变焦点、注入按键或使用剪贴板；不重放写操作。观察子进程退出前释放自身 UiAutomation 连接，避免与输入桥接争用。

本机 Android 15 专用测试 App 验收通过：两块屏幕存在同名输入框，副屏写入中英文后主屏控件属性不变；旧选择器被拒绝；真实 AndroidDevice → RPC → 桥接流程通过；副屏写入期间向主屏输入 `_user`，两边文字均正确，主屏仍持有输入焦点。未将此测试推论为所有 App 或全部键盘实现均兼容。
