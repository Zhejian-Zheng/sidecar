# Sidecar 接入 Dify 知识库 MCP：设计草案

日期：2026-10-11。状态：等待用户审阅；尚未实现。

## 目标与已确认条件

用户希望用 Dify 云端维护知识库，让现有手机 GUI Agent 通过 MCP 查询资料，辅助完成真实 App 任务。用户已在本地配置知识库 API 地址、密钥与知识库 ID。

本次只读连接检查返回 HTTP 200；查询“这个手机 Agent 项目需要提交哪些材料？”得到 3 个片段，其中包含仓库、演示视频和技术说明要求。检查不调用 DeepSeek、不操作设备，也不输出密钥。

目标示例：用户要求根据项目提交资料建立准备清单，Agent 检索资料、提取完成标准，再根据真实 App 界面完成操作与验证。

## 技术路线

采用本机 Python MCP 服务封装 Dify Knowledge API，由 Sidecar 的 MCP 客户端通过 stdio 调用。Dify 继续运行在云端，本地无需部署 Dify 或开放新的网络端口。

链路：Sidecar → 本地 MCP 服务 → Dify 检索 API → 带来源的资料片段 → 规划及 GUI 决策。

另外两种方式的取舍：Dify 原生 MCP 需要先创建并发布检索 Workflow；直接调用 HTTP 实现最少，但不满足本次明确提出的 MCP 接入目标。当前已有 Knowledge API 配置，采用本机薄封装可以直接复用。

MCP 必须使用实际的初始化、工具发现与调用协议，不把普通 HTTP 客户端命名为 MCP。使用官方 Python MCP SDK；本轮不引入 subagent 或通用 MCP 服务市场。

## 第一版工具与接口

只暴露 `sidecar_search_knowledge`。工具只读，不开放文档写入、删除、任意 URL、任意知识库选择或设备操作。

- 输入：`query`，1–250 字符。
- 知识库 ID、服务地址、密钥来自服务端配置，不能由模型覆盖。
- 输出：状态、检索片段、来源信息及是否截短。每条包含文档 ID、片段 ID、标题、内容和 Dify 返回的相关度；来源链接、版本和更新时间只在原始资料存在时保留。
- 首版最多向模型提供 3 个片段，每片段最多 1500 字符，总内容最多 4500 字符。截短必须显式标记；不能把相关度解释为事实正确率。
- 查询没有命中和接口失败必须区分，不能返回伪造答案。

## 配置与进程

沿用 `DIFY_API_BASE_URL`、`DIFY_KNOWLEDGE_API_KEY`、`DIFY_DATASET_ID`。在启动入口显式加载本地配置，已有进程环境变量优先；仅保存 `.env.example` 中的空占位，不修改用户密钥。

首版按 Dify 云端限制 HTTPS 服务地址，不跟随携带认证信息的重定向。MCP 子进程只接收运行所需环境和 Dify 配置；不传入 DeepSeek 密钥。设备 RPC 子进程剔除新加入的 Dify 凭证。

服务生命周期由 worker 管理。MCP stdout 只承载协议消息，日志不输出认证头、密钥或完整服务异常。HTTP 总超时设为 15 秒，单次 MCP 检索总预算 20 秒，首版不自动重试。

## Agent 中的调用时机

第一版采用受控检索：新任务可选择“使用知识库”，默认关闭。用户可填写不超过 250 字符的检索问题；没有单独问题时使用符合长度限制的任务目标。超长目标提示补充简短检索问题，不静默截断。

启用后，在新任务的规划前调用一次检索，将取得的参考资料传给规划和决策；这一步由 Harness 周边的任务准备流程管理，无需模型支持原生 MCP 或自由工具调用。

任务目标保持用户原文。完成标准可以引用检索出的任务资料，但不能据此扩大用户授权范围。知识库内容是参考数据，不能覆盖权限、取消、交接规则，也不能当作 App 已操作成功的证据。

已有任务恢复时沿用原任务、完成标准与保存的资料快照，不重新检索或重新规划。要使用更新后的资料，应明确发起新任务；本轮不加入自动后台刷新。

## 状态、失败与取消

给任务上下文增加可选的知识参考快照，保存查询、检索状态、取得时间、来源标识及受长度限制的内容。旧任务缺少该字段时按未启用知识库处理。

在 `queue.sqlite` 中增加按任务 ID 保存的准备记录，分别保存已经成功取得的资料快照与已经完成的计划。进入 Harness 后，将这些内容作为任务上下文持久化。旧任务没有准备记录时沿用原恢复流程。

检索或规划返回后，先保存相应阶段的结果，再响应暂停；恢复时只补做尚未完成的准备阶段，不重复已经完成的检索或规划。进程在结果持久化前崩溃仍按现有 interrupted 路径要求人工核对，不能保证这种情况下模型请求只发生一次。事件记录检索开始、成功、无结果、超时或失败，供现有执行记录展示；事件中不复制整篇文档。

开启知识库的任务，若无结果或检索失败，则在任何设备写操作之前结束准备阶段并解释原因。用户可以调整查询或关闭知识库后重新提交，不默默忽略任务依赖的资料。

检索前后及规划前后检查控制信号。取消优先于检索结果和异常写回；暂停不进入设备执行。尚未进入 Harness 的准备阶段失败不产生可恢复的假任务现场。检索期间的取消响应受上述超时上限约束。

## 代码范围

新增 Dify 只读客户端、MCP 服务和 MCP 客户端模块，保持三者职责分离。扩展任务提交与配置读取、规划/决策的参考资料输入、任务上下文持久化，以及网页中可选的知识库查询入口。

新增只读的知识检索检查入口，便于单独诊断 Dify 或 MCP 连接；不启动 Android 动作。更新 README、技术报告和示例配置，明确现有能力与尚未实现的功能。

## 验收

1. 用 MCP 协议发现且只能调用预期检索工具；工具结果经本地结构校验后进入上下文。
2. 离线测试覆盖有效片段、空结果、401/403、429、超时、无效 JSON、过大响应和缺失配置；异常不泄露密钥。
3. 配置优先级正确，未启用知识库的任务不发出检索请求，原有离线演示保持可用。
4. 检索和规划期间接受的取消不被覆盖；暂停时不执行设备动作；失败时不凭空补造资料。
5. 恢复不重复检索、不重规划，资料快照与原完成标准保持不变。
6. 包含越权指令的知识片段不能绕过 Harness 的动作限制；完成状态仍基于新的 App 观察验证。
7. 以当前项目要求文档完成一次真实 MCP 检索，检查返回来源与三项提交要求；此检查不等于真实 App 闭环验收。

## 第一版边界

不自动写回经验、不开放知识库编辑、不发送手机截图到 Dify、不做每步检索、不加入长期偏好系统。后续是否增加按失败状态补查，以首个真实任务的表现为依据。
