# 手机 GUI Agent 项目：任务与提交要求

资料类型：项目需求参考资料。
来源：项目所有者在本项目对话中提供的面试作业题目。
整理日期：2026-10-11。
适用范围：Sidecar 手机 GUI Agent 项目的准备、验收与提交。
资料边界：本文整理作业要求，不证明任何功能已经实现，也不记录当前任务完成情况。

## 项目目标

开发一个接受自然语言任务的手机 Agent。Agent 根据实时观察到的真实第三方 App 界面，自主决定多步操作，并处理弹窗、加载和页面变化。固定点击序列的回放不能满足 Agent 要求。

用户持续正常使用手机时，Agent 也应继续处理任务。不能依靠用户放下手机、锁屏或与 Agent 轮流操作来展示并行能力。任务结果必须真实作用于用户自己的 App 和账号。

## 不打扰与人工交接

Agent 不应切换用户的前台 App、抢占焦点或输入法，也不应导致明显卡顿。可以保留小型状态提示，用户应能发起任务、查看进度和随时接管。

遇到支付、登录、验证码等必须由用户本人处理的步骤，允许通过不抢占屏幕的方式请求介入，由用户决定何时及如何处理。主动交接不视为违反不打扰要求。

## 结果验证

Agent 宣告完成时，结果必须真实存在于目标 App 中，例如消息已经发出或事项已经创建。

如果需要人工交接，应明确已达成的边界，例如已经选好商品并停在支付页、等待用户确认。该边界本身也需要验证，不能把等待支付表述为购买已经完成。

## 技术路线与设备权限

题目不限定实现技术。模拟器、云手机或第二台手机可以作为方案，但需要在 README 和答辩中说明产品判断与技术取舍。

允许使用 ADB 等普通开发者能力，也允许 Root、系统签名或修改 ROM。使用特殊权限时，需在 README 中说明，并在答辩中解释如何在普通用户手机上落地。

WhalePhone 是期望产品体验的参考，不是指定实现方式。任务场景可自行选择，不强制覆盖多种任务；应优先证明同时操作、不干扰和结果真实。

## 需要提交的材料

1. GitHub 仓库链接，确保评审人员有访问权限。
2. 一段 1–2 分钟的演示视频。
3. 简要技术选型说明，可以放在 README 中。

演示视频需要在同一时间段展示：用户持续操作手机、Agent 的实际执行画面，以及最终结果。后台或虚拟屏的实时投屏可用于展示执行画面，仅有进度提示不足以证明执行过程。

题目规定收到题目后 5–7 天提交。实际收到题目的日期未在本资料中确定，因此不能据此推算具体截止日期。

## 30 分钟技术答辩的准备内容

答辩需要讲解架构及关键技术选择，说明为什么采用当前方案、为什么没有采用其他方案；需要演示核心功能、回答技术问题，并解释遇到的困难和解决思路。

如果使用 AI 辅助编码，应说明如何引导 AI、如何审查生成代码，以及如何作出架构决策。

未解决的问题应如实记录，包括调研内容、尝试方案和当前阻碍。不能把未完成或未验证的功能写成已经完成。
