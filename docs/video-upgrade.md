# 后台视频与结果证据升级

日期：2026-10-15。实现基线：main / 05d1bc2。

## 验收范围

- 隐藏副屏任务执行期间，持续采集画面；控制台可查看真实后台画面，并明确区分历史截图。
- 每次执行或恢复生成独立录像，结束后可经配对鉴权下载，不覆盖上一次尝试。
- 普通决策观察复用新收到的视频帧；视频不可用时只重试读取，不重放写入。
- 点击等动作执行前以及最终验证使用独立设备采集，不把解码接收时间当作设备截图时间。
- 屏幕身份、重启标识、尺寸发生变化时拒绝旧动作；保留现有定向文本输入。
- 受维护的验证规范随安装包加载到决策和验证提示词；记录观察编号、时间、方法、设备和规范摘要。
- 控制台与聊天入口共用结果格式函数，提供结构化报告接口。
- 不自动发送、支付，不把用户“继续”视为新增权限。

## 实现选择

`VideoSession` 是基础设施层资源管理器，由 worker 在一次任务执行期间持有。
其目录是 `.sidecar/recordings/<任务编号>/<本轮会话>/`，包括 `recording.mkv`、
`latest.png` 和 `stream.json`。暂停/等待用户/完成/失败退出本轮；恢复会创建新的目录。
控制台目前下载最新一轮；更早轮次保留在本地目录。录像包含实际 App 画面，不默认上传知识库。

两条视频通路各有用途：

1. scrcpy CLI `--record` 保存带设备时间戳的 MKV；关闭音频、控制和剪贴板同步。
2. 同一安装版本的 scrcpy-server 输出原始 H.264，经本地 ADB 转发及 FFmpeg 解码，
   供控制台和普通观察使用。服务端会检查版本匹配，不自行实现其控制二进制协议。

尝试直接追读尚在写入的 MKV 时，实测封装缓冲使画面延迟到结束才集中出现，
因此没有采用该方案。双路捕获增加编码资源开销；默认限制到 960 像素、每秒最多 5 帧，
尚未证明在各机型上都没有明显卡顿。未来可在固定版本下实现带设备时间戳的单路分发。

`latest_frame` 检查接收时间、运行状态与内容摘要，拒绝过期或混代图片。
接收时间只表示主机刚解码，不能证明画面没有传输积压。因此动作前复核和最终结果验证
仍通过 `observe_fresh` 使用独立、有超时的截图。流不可用时普通观察可降级到独立截图。
这不是“所有观察都已消除进程开销”，也不是端到端延迟保证。

`Observation` 携带显示会话与尺寸。动作前比较这些属性；设备执行入口再次比较尺寸。
文本输入继续使用定位控件的 textbridge，不切换到全局键盘或剪贴板。

## 启动与查看

继续使用原有 `serve --android --hidden-display` 启动方式，无需额外打开视频选项。
需 adb、scrcpy、FFmpeg 在 PATH，且安装 android 依赖。当前设备限制仍为 Android 15+。
服务端文件默认从 scrcpy 安装目录查找；非标准安装通过 `SCRCPY_SERVER_PATH` 指定
与 CLI **完全相同版本**的 scrcpy-server。当前实测为 scrcpy 5.0.1。

控制台点击“查看执行画面”，会每 500ms 请求最新帧。实时帧不可用时明确标注
“最近观察截图（非实时）”。本轮结束后显示“下载本轮执行录像”；不完整录像会标记。
所有媒体接口均要求原有 Bearer 配对令牌，不把令牌放到 URL。

- `GET /api/tasks/{id}/video`：本轮视频状态和录制状态。
- `GET /api/tasks/{id}/live-frame`：近期帧，缺失/过期返回 204。
- `GET /api/tasks/{id}/recording`：已结束本轮录像；未结束返回 409。
- `GET /api/tasks/{id}/report`：共享格式的结果文字及结构化验证记录。

## 验证与剩余边界

已在 Android 15 模拟器的独立副屏打开系统设置，验证连续帧推进、正常结束、录像生成，
并比较测试前后主屏前台一致。该测试不修改设置，也不证明用户同期持续打字。
自动化回归覆盖过期/停止/混代画面、屏幕尺寸变化、接口鉴权和任务隔离、可信规范加载、
最终验证独立取帧及证据来源字段。可选设备烟测见 `tests/test_video_live.py`。

结果仍使用模型依据新观察逐项判断；本次没有声称实现所有 App 的确定性结果验证器，
也没有自动证明跨设备账号同步、永久保存或用户支付成功。Google 时钟的独立重开核对
仍按演示指南执行。正式提交仍需录制用户持续操作与 Agent 实时画面同屏的 1–2 分钟视频。
