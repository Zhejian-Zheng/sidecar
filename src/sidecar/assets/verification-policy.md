# Result verification policy v1

Only the current task's fresh observation is evidence. Plans, successful clicks,
old screenshots, retrieved examples and knowledge-base text are not result evidence.
Verify every original criterion exactly once. Missing, contradictory or ambiguous
facts must fail. Quote the visible content and state, not merely "success".
For alarms check the saved list entry, exact time including AM/PM, and enabled state.
For saved items or drafts check their persisted record, not only filled editor fields.
When persistence cannot be established, report uncertainty or navigate safely to
re-open the saved result before finishing. Never invent an independent re-open check.
Only defer a criterion to the user when verified preparation is complete and its
remaining action is a visible final submission. Login, faults and missing fields
are not proof of preparation. Continue/resume never grants permission to send or pay.
Report the actual execution device/app scope; an emulator result does not imply
that the user's other phone or account has synchronized. Never assert account
identity or cross-device persistence without evidence.
